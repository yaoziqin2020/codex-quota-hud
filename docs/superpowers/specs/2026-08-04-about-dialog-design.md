# Codex Quota HUD “关于”窗口设计

日期：2026-08-04  
目标版本：1.2.0  
状态：已确认，待实施

## 目标

为普通用户提供一个明确、可发现的软件身份入口，使用户无需查看安装文件或 GitHub 页面即可确认当前版本、作者、项目地址和许可证。

## 已确认的用户体验

- 悬浮球右键菜单和系统托盘右键菜单都增加“关于”。
- “关于”位于“退出”上方；现有刷新、皮肤、动画、状态和退出行为不变。
- 点击“关于”打开一个小型独立窗口，不使用系统消息框，也不把版本信息直接塞进菜单。
- 重复触发时只保留一个“关于”窗口；已打开时将其带到前台，不叠加窗口。

## 窗口内容

窗口显示以下信息：

- 产品名称：`Codex Quota HUD`
- 当前版本：以 `版本 1.2.0` 的形式显示
- 作者：`老姚`
- GitHub：`yaoziqin2020/codex-quota-hud`
- 许可证：`MIT License`
- 一个“关闭”按钮

GitHub 文本可点击，并通过系统默认浏览器打开：

`https://github.com/yaoziqin2020/codex-quota-hud`

版本号必须从当前运行程序的程序集元数据读取，并格式化为三段语义版本号；不得在窗口代码中硬编码 `1.2.0`。这样正式版、预览模式以及未来版本都显示各自二进制文件的真实版本。

## 视觉与交互

- 使用与项目现有 WPF 窗口一致的 Windows 桌面风格，不引入新的 UI 框架或外部资源。
- 窗口尺寸保持紧凑，信息从上到下清晰排列。
- 显示应用图标和产品名称，版本、作者、GitHub、许可证作为次级信息。
- 窗口不可缩放，支持标题栏关闭按钮和底部“关闭”按钮。
- 窗口首次打开时位于当前屏幕的合理可见区域，不保存窗口位置或尺寸。
- GitHub 打开失败时显示简短错误提示，窗口保持打开。

## 代码结构

新增一个负责“关于”窗口生命周期的协调对象，由应用启动流程创建并供两套菜单共同调用。协调对象负责：

1. 首次请求时创建并显示窗口；
2. 窗口已存在时激活现有实例；
3. 窗口关闭后清除引用；
4. 应用退出时不留下独立窗口或后台进程。

悬浮球菜单和托盘菜单只负责调用同一个 `show about` 动作，不各自实现版本读取、链接打开或窗口管理。版本格式化与展示数据应与窗口布局分离，以便无 UI 测试验证。

## 菜单结构

两套菜单保持相同的尾部结构：

```text
上次更新：HH:mm（不可点击）
------------------------
关于
退出
```

不在“关于”和“退出”之间增加额外分隔线。

## 错误处理

- 无法读取程序集版本时显示可解释的回退值，例如 `未知`，不得导致 HUD 启动失败。
- GitHub 链接只能使用项目内固定的 HTTPS 地址。
- 默认浏览器启动失败时给出提示，不退出 HUD。
- “关于”窗口异常不得影响额度刷新、皮肤管理、动画或退出流程。

## 验证策略

自动验证至少覆盖：

- 版本元数据可被格式化为三段展示版本，且不暴露 `+commit` 等构建后缀；
- 缺少或异常版本元数据时使用安全回退值；
- 悬浮球菜单包含“关于”，且位于“退出”之前；
- 托盘菜单包含“关于”，且位于“退出”之前；
- 生命周期协调对象不会创建多个窗口；关闭后可以再次打开；
- GitHub 地址为确认过的项目 HTTPS 地址。

人工验证至少覆盖：

- 正式模式与 `--preview` 模式都能从悬浮球菜单打开窗口；
- 系统托盘菜单也能打开同一个窗口；
- v1.2.0 成品显示 `版本 1.2.0`；
- GitHub 链接能由默认浏览器打开；
- 关闭窗口后 HUD 继续正常运行；
- 多次点击不会叠加“关于”窗口。

## 非目标

本次不加入自动更新、检查新版本、反馈入口、隐私政策页面、设计器专属“关于”菜单或在线版本请求。皮肤设计器是否增加自己的“关于”入口留给后续独立需求，不扩大本次 HUD 菜单改动。

## 发布影响

本功能并入尚未完成安装验收的 v1.2.0。现有 v1.2.0 安装包是在本功能加入前生成的，因此实施完成后必须重新构建、重新计算校验值，并从真实安装流程重新验证；旧包不得作为最终 v1.2.0 发布成品。
