# Codex 剩余额度浮窗设计

## 目标

为 Windows 版 Codex 提供一个轻量、常驻但不打扰的桌面额度浮窗。浮窗只在 Codex 运行时显示，展示官方 `codex app-server` 能读取到的剩余额度；Codex 退出后浮窗自动隐藏。

“剩余百分比”统一按 `100 - usedPercent` 计算，避免把已用比例误标成剩余比例。

## 已确认的用户体验

- Windows 登录后启动一个隐藏监视进程，不主动显示窗口。
- 检测到 Codex 运行后显示桌面圆球；Codex 退出后隐藏。
- 圆球可拖动并记住上次位置；首次启动默认采用深色科幻 HUD 风格。
- 内置五套完整造型皮肤，而不是只替换配色：
  - `EnergyRing`：双彩能量环。
  - `LiquidGlass`：流体玻璃球。
  - `HudDial`：HUD 科技仪表，作为首次启动默认皮肤。
  - `Aurora`：克制极光。
  - `LiquidTank`：液位储能舱。
- 通过圆球右键菜单或托盘菜单切换皮肤，选择后立即生效并持久化。
- 环形轨道在待机显示时持续缓慢转动，表现为低频“扫描”状态。
- 发起额度请求时环形轨道平滑加速；请求结束后平滑减速回到待机速度，不突然跳变。
- 浮窗隐藏时暂停全部动画；用户关闭动画后保留静态进度环和请求状态变化，不再旋转。
- 正常情况下使用双环：
  - 中央数字和内环表示 5 小时额度的剩余百分比。
  - 外环表示每周额度的剩余百分比。
- 读不到 5 小时额度但能读到每周额度时，自动退化为单环，中央数字显示每周剩余百分比。
- 只读到 5 小时额度时，也退化为单环，中央数字显示 5 小时剩余百分比。
- 每套皮肤必须提供单额度形态：
  - 能量环、玻璃球、HUD 和极光皮肤移除承担缺失额度的第二层轨道。
  - 液位储能舱在双额度形态中用液面表示 5 小时、外环表示每周；单额度形态中移除外环，液面直接表示实际存在的额度。
- 单额度形态的中央标签明确显示“5 小时”或“每周”，不能只显示百分比让用户猜测。
- 两项额度都读不到时不显示圆球，不以 `0%`、占位符或错误信息冒充额度。
- 鼠标悬停显示详情卡片，其中只列出实际读到的额度、剩余比例、重置时间和最近更新时间。
- 后台每 60 秒读取一次；鼠标悬停时如果数据已超过 60 秒，则立即补一次刷新。
- 同一时间只允许一个实例运行。

## 技术方案

使用当前机器已经安装的 .NET 9 和 WPF 构建原生 Windows 小程序，不嵌入浏览器内核。选择 WPF 是因为它适合透明无边框、置顶、拖动和托盘交互，运行占用也明显低于附带 Chromium 的桌面壳。发布时生成 `win-x64` 自包含版本，目标机器无需另装 .NET 运行时。

程序拆分为以下边界：

1. `CodexProcessMonitor`
   - 只负责判断 Codex 是否正在运行并发出状态变化。
   - 不读取额度，不控制 UI。
2. `CodexAppServerClient`
   - 启动并管理 `codex app-server` 子进程。
   - 通过标准输入输出完成初始化和 `account/rateLimits/read` 请求。
   - 不关心圆环如何显示。
3. `RateLimitMapper`
   - 根据服务返回的窗口时长识别额度，不依赖数组顺序：
     - `300` 分钟识别为 5 小时窗口。
     - `10080` 分钟识别为每周窗口。
   - 把 `usedPercent` 转换成限制在 `0..100` 范围内的剩余百分比。
   - 缺失或格式异常的窗口返回“不可用”，不制造默认额度。
4. `QuotaRefreshService`
   - 在 Codex 运行时按 60 秒间隔刷新。
   - 防止并发刷新，并保留最后一次成功数据和时间。
   - Codex 未运行时停止额度子进程和定时读取。
5. `QuotaOrbWindow`
   - 根据可用额度选择双环、单环或隐藏。
   - 负责拖动、位置持久化、悬停详情和视觉动画。
   - 根据 `Idle`、`Refreshing` 状态平滑切换旋转速度；隐藏时停止动画时钟。
   - 通过统一的 `IQuotaSkin` 状态输入驱动五套皮肤，业务层不依赖具体造型。
6. `SkinController`
   - 注册 `EnergyRing`、`LiquidGlass`、`HudDial`、`Aurora`、`LiquidTank` 五套内置皮肤。
   - 负责即时切换、默认皮肤和已选皮肤持久化。
   - 向皮肤传入相同的双额度或单额度显示模型，禁止皮肤自行推断额度。
7. `TrayController`
   - 提供“立即刷新”和“退出”入口。
   - 提供五套皮肤的单选菜单，并与圆球右键菜单保持同步。
   - 浮窗隐藏时仍允许用户明确结束后台监视进程。
8. `SingleInstanceGuard`
   - 使用命名互斥量阻止重复实例。

## 数据流

1. 隐藏监视进程启动并取得单实例锁。
2. 进程监视器检查 Codex：
   - 未运行：保持浮窗隐藏。
   - 从未运行变为运行：启动额度客户端并立即读取一次。
3. 额度客户端取得原始限额数据，映射器按窗口时长识别 5 小时和每周额度。
4. UI 状态规则：
   - 两项可用：双环，中央显示 5 小时。
   - 仅一项可用：单环，中央显示该项。
   - 均不可用：隐藏。
   - 当前皮肤只消费上述显示状态，不改变额度识别结果。
5. Codex 运行期间每 60 秒重复读取。
6. Codex 退出后停止读取并隐藏浮窗。

## 动效状态

- `Hidden`：窗口隐藏，动画时钟停止。
- `Idle`：可见环以较慢速度持续旋转，数值保持稳定。
- `Refreshing`：请求开始后在短暂过渡中加速旋转，不改变旧数值。
- 请求成功：更新数值和详情，再平滑减速到 `Idle`。
- 请求失败：保留仍在有效期内的旧数据并平滑减速；没有有效数据则进入 `Hidden`。
- 双环使用相反方向或略有差异的速度，避免两条轨道视觉上粘成一条；单环沿用内环动效。
- 动效只使用 WPF 合成动画，不使用高频业务计时器驱动每一帧。

## 错误与降级

- 找不到 `codex` 命令、`app-server` 启动失败、响应超时或 JSON 无效时，本轮数据视为不可用。
- 单次刷新失败不弹系统错误；托盘菜单显示简短状态，便于排查。
- 如果已有成功数据，短暂读取失败时最多保留旧数据 5 分钟，并在悬停详情标记“数据可能已过期”；超过 5 分钟后隐藏浮窗。
- 不自动登录、不读取浏览器 Cookie、不抓取 Codex 页面、不保存 OAuth 令牌。
- 子进程只绑定当前应用，不开放网络端口。

## 配置和隐私

本地设置只保存：

- 浮窗坐标。
- 是否启用动画。
- 当前皮肤标识；无配置或配置无效时使用 `HudDial`。
- 最近一次成功刷新时间。

不持久化账号信息、额度响应正文或认证数据。设置保存在当前 Windows 用户的本地应用数据目录。

## 验证范围

自动测试覆盖：

- 5 小时与每周窗口的识别。
- `usedPercent` 到剩余百分比的转换和边界裁剪。
- 双环、两种单环、全隐藏四种状态选择。
- 五套皮肤在双额度和两种单额度状态下都能正确绑定显示模型。
- 皮肤即时切换、重启恢复以及无效皮肤配置回退到 `HudDial`。
- 无序窗口、缺失字段、异常 JSON 和刷新过期规则。
- 单实例保护。

人工验证覆盖：

- Windows 登录启动后无黑色命令窗口。
- Codex 启动/退出时浮窗显示与隐藏。
- 拖动后重启位置恢复。
- 悬停详情、双环和单环视觉。
- 五套皮肤、圆球右键切换、托盘切换以及选择持久化。
- 待机慢转、请求加速、结束减速以及隐藏后动画暂停。
- 任务管理器中的空闲占用与 60 秒刷新时的短时占用。

## 不在本次范围

- 修改 Codex 客户端本身。
- 绕过、预测或伪造官方额度。
- 多账号切换。
- macOS、Linux 或移动端版本。
- 永久在线服务、远程同步或云端存储。
